# 정책 엔진, 예산, 반복 방지

## 실행 단계별 서버 강제 검사

1. 스키마 검증: 미등록 tool/필드 거부.
2. 주체 확인: 로컬 MCP 클라이언트·OS 사용자·작업 ID 결합.
3. 정규화: 경로, 파일 핸들, 구조화 매개변수, 동작 fingerprint 생성.
4. 권한 확인: root allowlist, read/write 구분, 도구별 허용 여부.
5. 위험 평가: 범위/개수/바이트/특수 파일/서비스 영향.
6. 승인 검증: 필요한 경우 로컬 사용자 승인 증거와 plan hash 매칭.
7. 예산 차감·동시성 잠금: **실행 전** SQLite 트랜잭션으로 영속 기록.
8. 실행: 작업 경계(Job Object 등), deadline, heartbeat/감시자.
9. 검증: 예상 결과와 실제 결과 비교, 변경 hash/manifest 기록.
10. 완료/실패: 상태 확정, 리소스 회수, 필요 시 rollback; 무한 재시도 금지.

## 제안하는 초기 기본값 (성능 확인 후 조정)

| 제한 | 초기값 | 차단 방식 |
|---|---:|---|
| 단일 구조화 도구 호출 시간 | 30초 | 서버 deadline / 취소 |
| 장시간 허가된 작업 시간 | 120초 | Windows Job Object 프로세스 트리 종료 |
| 하나의 AI 작업 총 시간 | 15분 | task deadline, 새 호출 거부 |
| 작업당 최대 도구 호출 | 40회 | 영속 counter |
| 작업당 최대 변경 호출 | 12회 | 영속 counter |
| 동일 부작용 fingerprint 재실행 | 0회 자동 | 결과 조회 또는 명시적 새 승인 |
| 읽기 실패 자동 재시도 | 최대 2회 | 지수적 대기 후 오류 종료 |
| 의미 있는 진척 없는 연속 조회 | 5회 | 반복 경고/차단 |
| 전체 동시 작업 | 최대 2개 | 큐 및 리젝트 |
| 동시 변경 작업 | 최대 1개 | 전역 mutation lock |
| 작업당 수정 파일 수 | 최대 20개 | 사전 계획 분할 또는 승인 |
| 작업당 누적 쓰기 데이터 | 최대 50 MiB | 실행 전 예산 확인 |
| 출력 크기 | 호출당 최대 256 KiB | 자르기 및 요약 상태 반환 |
| 작업자 메모리 | 512 MiB 목표 | Job Object/별도 워커 메모리 제한 |
| CPU | 호스트 측정 후 제한 설정 | Job Object CPU rate control 검토 |
| 보호용 남은 디스크 공간 | 10 GiB 이상 | 부족 시 쓰기 중단 |
| 관리자 승인 | 2분·1회·계획 해시 고정 | 만료/변경/재사용 거부 |

> 숫자는 **설계 기본값**이며, 실제 JSCPC 하드웨어 측정 전 확정 값이 아니다. 요청별 작업 재시작으로 예산을 초기화하지 않도록 **호출자 단위 시간당·일일 상한**도 별도로 집행해야 한다.

## 무한루프·폭주 차단 상세

- AI가 같은 도구를 새 작업으로 여러 번 부르는 문제는 **global actor budget** 및 fingerprint 기록으로 막는다.
- 앱이 새 작업 ID를 만들어도 caller 시간당 호출/부작용 상한을 유지한다.
- `start_job` 반환 즉시 job handle을 저장하고 반복 조회에는 polling backoff/rate limit을 적용한다.
- 완료되지 않은 프로세스의 표준 출력이 무한 증가하지 않도록 링버퍼와 최대 로그 크기 적용.
- 실행 중 서버가 죽어도 Job Object KILL_ON_JOB_CLOSE 또는 감시자가 프로세스 트리를 수거한다.
- 같은 요청의 재시도는 작업 ID + idempotency key + input hash가 같을 때만 **이전 결과 조회**; 변경 재실행 금지.
- 진척/상태 판정은 모델 텍스트가 아니라 시스템 체크포인트(완료 파일·출력 해시·작업 상태 등)로 판단.
- watchdog이 반응하지 않으면 worker kill, 회복 모드에서 변경 기능 잠금.
- 서버가 실행하지 않는 외부 GPT 사고 루프/토큰 생성에는 이 제한이 미치지 않음.

## 보호 대상

- 파일: OS/부팅/드라이버 위치, 시스템 실행 파일, Windows 시스템 디렉터리, Program Files, 숨김 시스템 볼륨, 자격증명·인증서·SSH 키, 정책/로그/복원본.
- 서비스: `RpcSs`, `EventLog`, `WinDefend`, `BFE`, `MpsSvc`, `Schedule`, `wuauserv` 등 Windows 필수 및 보안 서비스. **이름 목록에만 의존하지 않음**; 모든 서비스 변경은 v1 차단.
- Docker: 직접 Docker Engine Pipe/Socket 접근 금지. 조회도 제한된 중개 API를 거친다. `docker system prune`, `docker volume rm`, `compose down -v`, `docker exec`와 임의 root mount는 v1 차단. 운영 서비스 restart는 별도 승인된 프로파일에서만 지원.
- 외부 네트워크 업로드·데이터 전송 도구는 v1 범위 밖. 민감 파일 읽기도 보호 대상임.

## 복구/비상 정지

- 로컬 관리자 CLI: `jscctl emergency-stop` → 모든 신규 작업 거부, 실행중인 제한 작업 중단, 잠금 플래그 영속 기록.
- 해제: 관리자 수동 `jscctl resume` 후 최근 오류/변경 계획 확인, 단순 서비스 재시작만으로 자동 해제되지 않음.
- 수정 전 snapshot, 삭제는 v1 원칙적으로 미지원(필요 시 사용자 휴지통 또는 격리 이동 + 승인).

## 변경 유형별 추가 심사

- 코드·설정 파일(`.ps1`, `.bat`, `.cmd`, `.exe`, `.dll`, `Dockerfile`, `.github/workflows`, 서비스 설정, 자동 실행 관련 파일)은 workspace 안이더라도 **실행 영향이 있는 변경**으로 분류해 별도 승인한다.
- `git`, CI, 배포 파이프라인, 바로가기/시작프로그램, 패키지 관리자 실행을 통해 간접적으로 OS 명령을 수행할 수 있는 우회 경로를 막는다.
- PowerShell `ConstrainedLanguage`나 실행 정책만으로 안전 경계를 만들지 않는다. 핵심 보호는 프로세스 권한·앱 제어·구조화 명령 allowlist다.
- 실수로 AI에게 자격증명·원격 저장소·외부 업로드 경로가 전달되어도 기본 네트워크 전송 차단 및 도구별 접근 정책으로 정보 유출 범위를 제한한다.
