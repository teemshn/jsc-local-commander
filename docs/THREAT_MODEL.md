# 위협 모델 (STRIDE 기반)

## 자산

- Windows 운영체제(시스템 파일, 레지스트리, 서비스, 부팅 구성)
- 업무용 파일·소스·DB·Docker 볼륨/실행 컨테이너
- 자격증명(GitHub 토큰, SSH 키, 브라우저 프로필, 인증서, NPKI)
- 작업 정책·승인 정보·감사 로그
- CPU·RAM·스토리지·네트워크 가용성

## 공격자/오작동 전제

- 사용자의 모호한 자연어 요청과 AI의 잘못된 추론
- 문서·로그·소스에 삽입된 명령형 문장(prompt injection)
- MCP 클라이언트의 실수·권한 오용
- 공격자가 수정한 워크스페이스 파일·경로·junction
- 무한 반복/재시도 폭주, 병렬 작업 충돌
- 정책 변경·프로세스 중단·감사 로그 변조 시도

## 위협과 통제

| 시나리오 | 영향 | 방어 | 잔여 위험 |
|---|---|---|---|
| '폴더 정리'가 C:\Windows 파일 삭제로 해석 | 부팅 장애 | OS ACL + workspace allowlist + 파괴적 도구 미제공 | 권한 상승/취약점 시 통제 우회 |
| 경로가 junction으로 시스템 폴더 연결 | 의도치 않은 중요 파일 수정 | reparse 차단 + 핸들/볼륨 기반 재검증 | 경합/특수 파일 시스템 버그 |
| 로그 속 '기밀 파일 업로드' 명령을 AI가 따름 | 정보 유출 | 민감 경로 접근 불가 + 네트워크 전송 도구 부재 | 이미 허용된 콘텐츠의 노출 |
| 같은 변경 요청 수백 번 재시도 | 데이터 손상·고갈 | 중복 fingerprint, persistent budget, idempotency | 교묘하게 다른 요청으로 변조 가능 |
| PowerShell 무한 루프 + 자식 프로세스 증식 | CPU/RAM 고갈 | raw shell 미제공 + Job Objects + watchdog + 작업 시간 제한 | 커널/드라이버 문제는 범위 밖 |
| Docker 서비스 또는 DB 종료 | 서비스 중단 | v1 읽기 전용, 변경 명령 승인 필요, 운영 컨테이너 denylist | 별도 관리자 도구 우회 |
| 모델에게 '승인했다'고 말함 | 권한 위조 | OS 로컬 CLI에서만 서명된 단기 일회 승인 | 승인자 실수 |
| 서버가 재시작되며 예산 초기화 | 반복 제한 우회 | SQLite 영속 counter + 미완료 작업 격리 | DB 손상 시 deny all |
| MCP 서버가 SYSTEM 계정으로 실행됨 | OS 전체 손상 | 설치 전 계정/권한 필수 검사, SYSTEM/admin이면 실행 거부 | 잘못된 배포 정책 |
| 저장 용량 소진 | 서비스 장애 | 복원본/출력 상한 + 최소 남은 공간, 용량 예약 | 외부 프로세스가 용량 사용 |
| 다른 SSH MCP에서 root/admin 명령 실행 | 정책 완전 우회 | 고권한 도구/계정을 기본 AI 프로필에서 분리 | 외부 도구를 쓰는 사용자의 통제 필요 |
| AI가 CLI 명령 수행 승인 자체를 조작 | 권한 상승 | 승인은 AI 도구로 수행 불가, 별도 사용자 터미널 | 로컬 계정 탈취 |

## 보안 보증 한계

`denied_paths`나 AI 시스템 프롬프트만으로 OS 보호를 주장하지 않는다. 실제 강제 경계는 Windows 토큰/ACL 및 작업 실행기 정책이다. Windows Job Objects는 자원 관리 수단이지 VM 수준 보안 샌드박스가 아니다.
