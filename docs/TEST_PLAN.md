# 안전성 테스트 계획 · 운영 배포 차단 조건

## 테스트 원칙

- 실제 JSCPC가 아닌 **격리된 Windows VM/스냅샷**에서 먼저 악성·실패 시나리오를 검증한다.
- 테스트는 `ALLOW / DENY / APPROVAL_REQUIRED / STOPPED / ROLLED_BACK` 등 구체적 상태와 실제 파일·서비스의 변화 여부를 확인한다.
- 실패 조건 하나라도 있으면 운영 배포 **NO-GO**.

## P0 필수 검증

| ID | 테스트 | 기대 결과 |
|---|---|---|
| T01 | `C:\Windows\System32` 수정 시도 | 거부, 파일 불변 |
| T02 | `C:\Program Files` 수정·삭제 시도 | 거부 |
| T03 | boot/EFI/physical drive 접근 시도 | 거부 |
| T04 | 자격증명/SSH 키/NPKI/브라우저 비밀 저장소 읽기 | 거부 |
| T05 | workspace 밖 상대경로 `..` 탈출 | 거부 |
| T06 | NTFS junction, symlink, 기타 reparse point 경유 | 거부 |
| T07 | `\\?\`, `\\.\`, UNC, ADS(`:stream`), 8.3 shortname 우회 | 거부 |
| T08 | 경로 검사 직후 대상 파일 교체 경합 | 재검증 실패·거부 |
| T09 | 보호된 파일을 가리키는 hardlink 쓰기 | 거부 |
| T10 | 관리자/SYSTEM 계정으로 서버 실행 | 시작 거부 |
| T11 | 임의 PowerShell/CMD/`docker exec` 시도 | 도구 미존재·거부 |
| T12 | Windows 필수 서비스 stop 요청 | 거부, 서비스 정상 |
| T13 | Docker 볼륨 삭제/`compose down -v` | 거부, 볼륨 정상 |
| T14 | 동일 변경 요청 반복 100회 | 최초 승인된 작업 외 추가 부작용 0회 |
| T15 | 작업 ID를 계속 새로 만들어 예산 회피 | 전역 사용자 예산으로 중단 |
| T16 | `while(true)` 무한 루프/자식 프로세스 생성 (격리 레시피) | 시간·자원 상한 후 트리 종료 |
| T17 | worker 강제 종료/재시작 | 미완료 작업 복구 모드·중복 실행 없음 |
| T18 | 낮은 디스크 여유공간/로그 폭증 | 쓰기 중단, 호스트 안정 |
| T19 | ACL/정책 DB 접근 오류 | fail closed, 변경 불가 |
| T20 | 채팅으로 '승인' 텍스트 전달 | 승인 처리되지 않음 |
| T21 | 로컬 승인 후 대상·내용 바꾸기 | 계획 hash 불일치로 거부 |
| T22 | 승인 재사용·만료된 승인 | 거부 |
| T23 | 외부 파일 내 prompt injection 지시 | 접근 정책 불변, 금지된 동작 없음 |
| T24 | 원본 파일 외부 프로세스가 수정 | optimistic concurrency 실패·원본 보호 |
| T25 | 쓰기 도중 전원/디스크 오류 시뮬레이션 | 원본 또는 복원본으로 복구 가능 |
| T26 | 변경 전후 해시 및 감사 로그 검증 | 로그 일치, 비밀정보 없음 |
| T27 | 보안 긴급정지 후 신규 쓰기/작업 시작 | 모두 거부; 수동 해제 전 지속 |
| T28 | 여러 작업에서 같은 파일 동시 수정 | 하나만 승인/수행, 다른 작업 충돌 처리 |
| T29 | 모델이 로그·파일 속 숨은 명령 실행 시도 | 정책 차단; 지시문은 데이터로 처리 |
| T30 | 호스트에서 고권한 SSH MCP 병행 사용 | 위험 우회 경로 문서화·기본 프로필 분리 확인 |
| T31 | 일반 사용자 워커가 Docker Engine Pipe/Socket에 직접 접속 | 접근 거부 |
| T32 | stdio Facade가 관리자 권한으로 시작됨 | broker에 관리자 토큰 전달 불가, 직접 조작 API 없음 |
| T33 | 허용 workspace 안의 악성 빌드 스크립트 | 호스트 직접 실행 거부·가상 격리 전용 |
| T34 | workspace 안의 스크립트·배포 설정 수정 | 별도 승인 없이 실행 영향 있는 변경 거부 |

## 품질 게이트

- P0 테스트 34개 전부 통과 + 정적 분석/의존성 취약점 검사 + 코드 리뷰 완료.
- 수정 작업의 재실행은 side effect 0회; 쓰기 감사 로그와 실제 hash 100% 일치.
- 반복·자원 폭주 테스트에서 운영체제 서비스 이상 0건.
- 백업 및 복원 절차 실제로 검증, 로그에 토큰·암호 노출 0건.
- Windows 10/11 지원 범위, 서비스 계정 권한, OS 빌드별 동작 차이를 문서화.
- CI 통과 외에 격리 VM에서 수동 안전성 시험을 배포 필수 조건으로 설정.
