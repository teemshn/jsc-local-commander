# 운영·승인·사고 대응 (제안)

## 초기 운용

- 실행은 사용자 세션의 Codex CLI와 `stdio`로 한정한다. 관리자는 `jscctl status`로 정책 상태를 조회한다.
- 최초 설치는 관리자가 수행하되 MCP 실행 워커에는 절대 관리자 권한을 부여하지 않는다. stdio facade(사용자 세션)와 broker(제한 서비스)를 OS 수준의 권한 경계로 분리한다.
- 정책 파일의 쓰기 권한은 관리자로 제한. 모델이 tool로 정책을 수정할 수 없어야 한다.
- 민감경로 읽기와 외부 송신은 별도 승인 없이 금지.

## 변경 승인

1. MCP가 변경 계획 `plan_id`, hash, 예상 대상/변경 파일 목록을 반환.
2. 사용자가 별도 로컬 콘솔에서 `jscctl pending`으로 계획과 영향을 검토.
3. 승인 필요성이 인정되면 `jscctl approve <request-id>`를 **직접 입력**.
4. 서버가 짧은 유효기간·일회용 승인과 실제 실행 인자 일치 여부를 확인.
5. 변경 후 diff/hash/로그를 확인; 불일치 시 자동 추가 수정 대신 중단.

## 긴급 중단

- `jscctl emergency-stop`: 모든 새 명령 차단, 작업 종료, 사건 기록.
- 개발/운영 버전에서 이 명령은 모델에게 노출되지 않음.
- 자동 재시작해도 위험 상태 잠금 유지.
- 서버 설치 전에는 이런 명령이 **존재하지 않음**. 단지 개발 요구사항임.

## 기존 도구와의 관계

- 기존 JSC SSH MCP와 Remote Desktop Commander가 같은 JSCPC에서 관리자 권한 명령을 실행하면 이 서버 보호를 우회할 수 있다.
- 일반 자동화 프로필은 이 MCP만 노출하고 고권한 도구 접근을 분리.
- MCP의 원격 통신을 끈 상태에서는 ChatGPT 웹/모바일이 로컬 stdio 서버에 직접 접근하지 못한다.

## 업데이트

- 의존성 버전 고정/서명/취약점 스캔 후 반영.
- 자동 업데이트로 tool schema나 권한이 바뀌지 않도록 버전 업그레이드 승인.
- 보안 정책 변경마다 위협 모델 및 30개 필수 테스트 재실행.
