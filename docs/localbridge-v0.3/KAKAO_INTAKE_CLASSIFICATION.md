# KakaoTalk 업무자료 자동분류 설계 — 연결 방식과 검증 기준

상태: DESIGN / 2026-11-20 / 사용자 제공 카카오톡 캡처의 "카카오톡 연동 자동분류" 경험을 실증 사실로 오해하지 않을 것.
회사 카카오톡/개인 카카오톡 API 인증·파일 수신/다운로드 기능은 아직 실제 연결하지 않음.
기존 JSC Local Commander v0.2 main 불변.

## 1. 확인된 카카오 공식 지원 범위와 핵심 제약
- 카카오 공식 KakaoTalk Message API는 주로 메시지 발송용이며 개인·단체 채팅방의 과거 대화/첨부를 수신·열람하는 공개 API는 제공하지 않는다고 Kakao DevTalk에서 안내한다.
  https://devtalk.kakao.com/t/api/127273
  https://devtalk.kakao.com/t/topic/141667
- 카카오톡 채널/챗봇은 고객이 채널·봇으로 새로 제출한 메시지에 대해, 승인된 챗봇 스킬 API 등으로 별도 업무 시스템과 연동할 수 있으나 개인/단톡 내역과 동일하지 않다.
  https://business.kakao.com/info/chatbot/
  https://developers.kakao.com/docs/ko/kakaotalk-channel/common
- 공식 API를 이용해 임의 개인·그룹 대화를 무인 수집한다는 주장은 불가. 캡처 작성자가 어떻게 실현했는지는 미확인: 공식 채널/스크린 UI/수동 내보내기/다운로드 폴더/비공식 클라이언트 중 무엇인지 단정하지 않음.

## 2. 목적
업무 직원이 카카오톡으로 전달받은 파일·지시사항을 본인의 명시적 동의·회사 정책과 개인정보 최소화 조건 안에서 접수해 분류하고, 필요하면 PDF/HWP/DWG/Excel 후속 작업 계획을 생성하는 시스템. 파일을 '자동으로 삭제/이동/변경'하지 않고 검증된 새 보관 사본과 색인을 만드는 것이 1차 목표.

## 3. 수집 인터페이스별 위험도
| 모드 | 동작 | 가능한 범위 | 초기 채택 |
|---|---|---|---|
| A. 사용자 전달함 | 사용자가 해당 메시지의 파일을 LocalBridge 인박스 폴더로 다운로드/공유·드래그 또는 앱의 전달 메뉴를 이용 | 사용자가 직접 제공한 자료만, 첨부 원본·내용 확인 가능 | 권장 MVP |
| B. 허가된 PC 다운로드 폴더 감시 | 사용자가 카카오톡 PC에서 저장한 파일이 승인된 특정 폴더에 들어오면 검증 후 분류 | 파일 저장 이후의 자료; 저장 전 대화 본문/기존 채팅 불가 | 권장 2단계 |
| C. 공식 비즈니스 채널·챗봇 | 소유한 카카오톡 채널의 승인된 챗봇 대화 이벤트를 공식 스킬 API로 처리 | 새로 그 채널로 보낸 업무 자료·입력 데이터, 서비스 조건/첨부 지원 확인 필요 | 업무용 채널 도입 시 |
| D. 사용자 동의 PC 카카오톡 UIA | 로그인된 카카오톡 PC 창에서 접근 가능한 화면/알림을 제한적 읽기 | UI 변경, 포커스, 잠금, 개인정보, 카카오 정책 검토 필요. 과거 대화 전량 추출 또는 무단 수집 아님 | 연구·옵트인 후순위 |
| E. 개인·단톡 API 대화 전체 수집 | 공식 제공되지 않는 API 기능 요구 | 제공 불가 | 미지원 |

자동분류와 자동수집은 다른 문제다. 자동분류는 인박스로 합법적으로 도착한 파일만으로도 구현 가능하다.

## 4. 추천 첫 버전 구조
카카오톡 PC/모바일 [사용자가 파일을 저장하거나 전달]
  → 승인된 Windows LocalBridge Inbox (단일 전용 폴더)
  → Event Collector (filesystem watcher + bounded debounce + 주기적 저빈도 reconciliation)
  → quarantine / 파일 안전 검사 (완료된 다운로드만, symlink 거부, 크기 및 확장자 제한, 바이러스 검사, hash, MIME)
  → metadata extractor (파일명, 날짜, 수정시간, 제출자/출처는 사용자가 제공하는 경우에만)
  → document inspectors (PDF text, HWP rhwp read-only, DWG OCS read-only, XLSX safe parser)
  → local classifier (project/contract type/category/priority/confidence/evidence)
  → SQLite 인덱스(경로·파일 ID·해시·분류 근거·처리 상태)
  → 검토함/확정 폴더에 사본 + 선택적 Google Drive 동기화(회사 정책과 승인 필요)
  → 선택적 승인 후 업무 문서 편집 작업 계획 (직접 수정 실행과 분리)

## 5. 처리 상태
RECEIVED → STABLE_FILE → VALIDATED → EXTRACTED → CLASSIFIED → REVIEW_PENDING → APPROVED → ARCHIVED
       → DUPLICATE / UNSUPPORTED / QUARANTINED / FAILED / NEEDS_REVIEW.

- 어떤 단계에서든 오류 발생 시 원본 파일을 지우지 않는다.
- 전자서명/날인/암호 문서는 추출 불가 시 보류. 확장자만 믿지 않고 실제 포맷 점검.
- confidence가 낮거나 공사명/계약건이 여러 개로 매칭되면 미분류·사람 검토.
- 학습/추론은 초기 무료 규칙 기반 + 로컬 전용 처리 우선; 유료 LLM API를 자동 호출하지 않는다. ChatGPT 구독과 API 과금은 별개일 수 있음.
- 동일 내용 반복수신: SHA-256 + 파일 크기 + 입력 경로 + 기록된 출처 ID로 중복 판정. 같은 이름의 다른 문서는 합치지 않는다.
- 고정 분류 예시: 공사명 / 업체명 / 계약번호 / 수신일 / 문서종류 (시방서, 내역서, 도면, 계약서, 세금계산서 등), 기밀 등급, 출처, 처리상태.
- 파일명에서 추출한 업체명/공사명은 단서이며 다른 증거와 대조; 확신도 없는 항목을 단정하지 않는다.

## 6. 성능·안전 상한 (실기기 조정 전 설계 기본값)
- 동시 파일 인제스트: 최대 2, 문서 내 OCR/PDF 렌더: 최대 1.
- watcher 폭주 예방: 1초 디바운스, 매 10~30분 reconciliation 시 총 검사 파일수 상한.
- 한 파일 최대 25MiB로 시작, 문서유형별 별도 한도; 대용량 DWG는 메타데이터만 보고 별도 승인을 통해 정밀 분석.
- 파일 다운로드 완료: 크기·mtime 연속 2회 동일 및 잠금 여부 확인, 최대 3회 제한된 재확인 후 QUARANTINED/REVIEW.
- 소스 파일 수정/삭제/원본 이름 변경 금지. 복사본 저장, 각 처리의 SHA-256 영수증.
- 백업 저장량/로그 크기/인덱스 DB 규모/CPU/RAM/디스크 여유 최소치 사전 점검.
- 첨부에 바이너리·실행파일·매크로가 포함돼도 자동 실행하지 않음.
- 카카오 개인/단톡 내용을 허가 없이 광범위하게 수집하거나 비공식 프라이빗 API에 로그인하지 않음.
- 회사 자료의 GitHub/외부 클라우드 무단 전송 금지, 로그에 고객 인적사항과 채팅 내용 원문 남기지 않음.
- 전송자 의도·회사 정책이 확인되지 않은 제3자 대화 수집은 금지.

## 8. MVP 실증 순서
1. 사용자가 직접 만들어 제공한 합성 카카오톡 파일명 및 몇 개의 샘플(PDF/HWP/HWPX/DWG/XLSX)으로, 실제 카카오 계정 연결 없이 Windows 인박스 감시/중복방지/분류 시험.
2. 사람이 승인한 전용 폴더에 카카오톡 PC로 한 건 다운로드, 1회 자동분류·원본 불변·결과 확인.
3. 상담/비즈니스 채널을 실제로 운영하는 경우 공식 챗봇 스킬 API 권한과 첨부 자료 전달 구조 실증.
4. 개인/단체방의 실시간 전체 자동 수집이 절대 필요하면 정책·법률·사용자 명시적 동의 및 해당 앱의 접근 인터페이스 검증을 선행. 공식 API와 동일한 권한이 있다고 간주하지 않는다.

이 기능은 ChatGPT 모바일에서 업무 PC 제어 연결과 독립적으로 구현/검증할 수 있다.
